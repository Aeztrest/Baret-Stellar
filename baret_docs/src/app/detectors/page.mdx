# Risk Detectors

Baret runs a set of independent detectors on every transaction. Each reports zero or more **findings** in `riskFindings`, and each finding has a `code`, a `severity` (`low`, `medium` or `high`), a message and optional details. {{ className: 'lead' }}

Findings are **advisory by default**. A finding only makes the verdict `safe: false` when the policy option named beside it is on. That keeps the API honest about what it saw while letting you decide what counts as a block. See [Policy](/policies).

<Note>
  This page is generated from the server's own catalog. The live, always-current
  list is `GET /v1/detectors` (no key needed; filter with `?status=active`,
  `?status=reserved` or `?category=`). Codes marked **reserved** exist in the response
  type so integrations can be forward compatible, but nothing emits them yet:
  do not wait for them.
</Note>

Two behaviours worth knowing: an empty policy still blocks a failed Soroban simulation and incomplete data (`LOW_CONFIDENCE_INCOMPLETE_DATA`, unless `allowWarnings` is true); and the reputation check uses a very small seed list, so no `KNOWN_MALICIOUS_ADDRESS` finding is not evidence of safety.

## Simulation {{ id: 'simulation' }}

<Properties>
  <Property name="SIMULATION_FAILED" type="high">
    Soroban preflight rejected the transaction, so it would very likely fail on-chain. Blocks when `requireSuccessfulSimulation` is on.
  </Property>
  <Property name="SIMULATION_ERROR" type="high (reserved)">
    Reserved for infrastructure errors while simulating. Nothing emits this code yet.
  </Property>
  <Property name="LOW_CONFIDENCE_INCOMPLETE_DATA" type="medium / high">
    The analyzer could not see the whole transaction: a Soroban call ran without preflight, an amount could not be parsed, accounts were truncated, the auth tree exceeded the parser's safety cap, or a balance rule was set without `userWallet`. Blocks unless `allowWarnings` is true. Blocks when `allowWarnings` is on.
  </Property>
</Properties>

## Account takeover {{ id: 'account' }}

<Properties>
  <Property name="ACCOUNT_MERGE_DETECTED" type="high">
    An AccountMerge operation moves an account's entire XLM balance to another account and permanently closes it. Blocks when `blockAccountMerge` is on.
  </Property>
  <Property name="MASTER_KEY_REMOVED" type="high">
    SetOptions sets the master key weight to 0, so the account's own key can no longer sign for it. Blocks when `blockMasterKeyRemoval` is on.
  </Property>
  <Property name="SIGNER_CHANGE_DETECTED" type="medium / high">
    SetOptions adds, updates or removes a signer. Granting weight to an unknown key hands over control of the account (high); removing a signer is medium. Blocks when `blockSignerChanges` is on.
  </Property>
  <Property name="THRESHOLD_CHANGE_DETECTED" type="medium">
    SetOptions changes the low, medium or high signing threshold. Blocks when `blockSignerChanges` is on.
  </Property>
  <Property name="SET_OPTIONS_RISKY" type="medium">
    SetOptions sets or clears account flags (AUTH_REQUIRED, AUTH_REVOCABLE, AUTH_IMMUTABLE, AUTH_CLAWBACK_ENABLED). AUTH_IMMUTABLE cannot be undone. Advisory: reported but never blocks on its own.
  </Property>
</Properties>

## Balance and loss {{ id: 'balance' }}

<Properties>
  <Property name="POST_BALANCE_TOO_LOW" type="high">
    After the transaction, `userWallet` would hold less of `minPostAsset` than `minPostUsdcBalance`. Also fires (fail-closed) when the balance cannot be projected. Blocks when `minPostUsdcBalance` is on.
  </Property>
  <Property name="ESTIMATED_LOSS_EXCEEDS_MAX" type="high">
    The wallet's native XLM balance would fall by more than `maxLossPercent`. Blocks when `maxLossPercent` is on.
  </Property>
  <Property name="LOSS_PERCENT_UNAVAILABLE" type="high">
    `maxLossPercent` was set but there is no `userWallet` or no pre-state to compute it from. Blocks (fail-closed). Blocks when `maxLossPercent` is on.
  </Property>
</Properties>

## Contracts and reputation {{ id: 'contracts' }}

<Properties>
  <Property name="RISKY_CONTRACT_INTERACTION" type="high">
    The transaction touches a contract on the server operator's risky-contract list. Blocks when `blockRiskyContracts` is on.
  </Property>
  <Property name="UNKNOWN_CONTRACT_EXPOSURE" type="medium">
    The operator configured a known-safe contract list and this transaction touches a contract that is not on it. Only fires when that list is configured. Blocks when `blockUnknownContractExposure` is on.
  </Property>
  <Property name="KNOWN_MALICIOUS_ADDRESS" type="low / medium / high">
    An account or contract in the transaction matches the server's reputation list. The list is a small seed set today, so absence of this finding is not evidence of safety. Advisory: reported but never blocks on its own.
  </Property>
  <Property name="SUSPICIOUS_CONTRACT_AGE" type="medium (reserved)">
    Reserved for very recently deployed contracts. Nothing emits this code yet.
  </Property>
</Properties>

## Fees {{ id: 'fees' }}

<Properties>
  <Property name="EXCESSIVE_RESOURCE_FEE" type="medium / high">
    Soroban's minimum resource fee exceeds the cap (`maxResourceFeeStroops`, default 5 XLM). High when you set the cap, medium for the default. Advisory: reported but never blocks on its own.
  </Property>
  <Property name="EXCESSIVE_BASE_FEE" type="medium / high">
    The total transaction fee exceeds the cap (`maxBaseFeeStroops`, default 0.1 XLM). High when you set the cap, medium for the default. Advisory: reported but never blocks on its own.
  </Property>
</Properties>

## x402 payments {{ id: 'x402' }}

<Properties>
  <Property name="X402_SHAPE_INVALID" type="high (reserved)">
    Reserved for x402 payments that do not match the expected shape. Nothing emits this code yet.
  </Property>
  <Property name="X402_MEMO_MISSING" type="medium">
    `requireMemo` is set and the transaction has no memo. Blocks when `requireMemo` is on.
  </Property>
  <Property name="X402_DESTINATION_MISMATCH" type="high">

    With `paymentRequirements`, the required asset is not referenced by the transaction. Advisory: reported but never blocks on its own.
  </Property>
  <Property name="X402_AMOUNT_MISMATCH" type="high (reserved)">
    Reserved for a paid amount that differs from the requirements. Nothing emits this code yet.
  </Property>
  <Property name="X402_FACILITATOR_MISMATCH" type="high (reserved)">
    Reserved for an unexpected fee payer / facilitator. Nothing emits this code yet.
  </Property>
  <Property name="X402_NON_CANONICAL_ASSET" type="medium">
    An asset in the transaction is not on the policy's `allowedAssets` list. Blocks when `allowedAssets` is on.
  </Property>
</Properties>

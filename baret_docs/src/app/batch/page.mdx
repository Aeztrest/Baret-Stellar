# Batch Analysis

Send up to 25 transactions in one call. The items run independently and in parallel, and the response keeps the order of your input. One item failing does not fail the request. {{ className: 'lead' }}

---

## Analyze a batch {{ tag: 'POST', label: '/v1/analyze/batch', id: 'analyze-a-batch' }}

<Row>
  <Col>

    ### Required attributes

    <Properties>
      <Property name="transactions" type="array">
        1 to 25 objects. Each has the same shape as the body of [`POST /v1/analyze`](/analyze): `network` and `transactionXdr` are required; `policy`, `userWallet`, `integratorRequestId` and `paymentRequirements` are optional. **Each item carries its own `policy`**; there is no batch-level policy.
      </Property>
    </Properties>

    ### The response

    <Properties>
      <Property name="count" type="integer">
        Number of results (equal to the number of transactions sent).
      </Property>
      <Property name="results" type="array">
        One entry per input, in order. Each has `index` and `status`: `success` (with the full `decision`, the same object `/v1/analyze` returns) or `error` (with `error.code` and `error.message`, using the codes in [Errors](/errors)).
      </Property>
      <Property name="summary" type="object">
        `safe`, `blocked` and `errors` counts.
      </Property>
    </Properties>

    A batch is one HTTP request but counts as one request **per item** against your key's per-minute limit, so a batch of 25 uses 25 of your 60 requests. An invalid body (more than 25 items, or an item missing `transactionXdr`) is rejected as a whole with `400 BAD_REQUEST`.

  </Col>

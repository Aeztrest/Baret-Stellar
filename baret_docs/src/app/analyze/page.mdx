# Analyze Transaction

The core call. Send a base64 `TransactionEnvelope` and get back what it would do, what is risky about it, and whether your policy blocks it, before anyone signs. {{ className: 'lead' }}

---

## The decision object {{ id: 'the-decision-object' }}

`POST /v1/analyze` returns this object. (`/v1/analyze/batch` and `/v1/analyze/stream` return the same object per transaction.)

<Properties>
  <Property name="safe" type="boolean">
    `false` means your policy blocks the transaction. It is also `false` when the Soroban simulation failed (unless you turned `requireSuccessfulSimulation` off) or the analysis had incomplete data (unless `allowWarnings` is true).
  </Property>
  <Property name="reasons" type="string[]">
    Plain-English sentences behind the verdict. They are for people and may change; branch on `riskFindings[].code` instead.
  </Property>
  <Property name="riskFindings" type="array">
    Each finding has a `code`, a `severity` (`low`, `medium` or `high`), a `message` and optional `details`. A finding is advisory unless the matching policy option is on. See [Risk detectors](/detectors).
  </Property>
  <Property name="estimatedChanges" type="object">
    `native`: XLM per account (`preStroops`, `postStroops`, `deltaStroops`, all strings, 1 XLM = 10,000,000 stroops). `assets`: issued-asset and Soroban token balance changes. `trustlines`: opened, changed or removed. `allowances`: Soroban `approve` grants (`spender`, `amount`, `expirationLedger`).
  </Property>
  <Property name="simulationWarnings" type="string[]">
    Reserved for human-readable simulation warnings. Currently always empty.
  </Property>
  <Property name="annotation" type="object">
    `summary`: the operations in plain language (`operations`, `humanReadable`, `primaryAction`, `involvedContracts`, `involvedAssets`). `cpiTrace`: the Soroban authorization tree (`roots`, `allContractAddresses`, `maxDepth`, `totalInvocations`).
  </Property>
  <Property name="suggestions" type="array">
    Optional advice such as a high fee or an unlimited approval. Never blocks. Each has `id`, `severity` (`info`, `warning`, `critical`), `category`, `title`, `description`.
  </Property>
  <Property name="meta" type="object">
    `analysisVersion`, `network`, `simulatedAt`, `confidence` and your `integratorRequestId`. `confidence` is `high` when Soroban preflight ran, `medium` for classic-only transactions (there is nothing to preflight), and `low` when data was incomplete or the simulation failed.
  </Property>
  <Property name="attestation" type="object">
    Present only when the server signs its verdicts: `signature`, `signerPublicKey`, `signedAt`, `nonce`. See below.
  </Property>
</Properties>

<Note>
  The result is a **simulation against current chain state**, not a promise about
  what will happen on-chain: fees, sequence numbers, time bounds and ledger state
  can change between analysis and execution.
</Note>

### Verifying a signed verdict

If `GET /v1/meta` shows `attestation.enabled`, every response carries an Ed25519 signature over the transaction hash, `safe`, a digest of `riskFindings`, `signedAt` and `nonce`. The transaction hash is **not** in the response: compute it yourself from the XDR you sent (the hash of the inner transaction for a fee-bump), so a compromised server cannot sign a verdict for a different transaction. Pin the server's public key, obtained out of band. The `@stellar-thorn/agent-guard` SDK does this for you (see [SDKs](/sdks)).

## Analyze a transaction {{ tag: 'POST', label: '/v1/analyze', id: 'analyze-a-transaction' }}

<Row>
  <Col>

    Analyze one transaction. Signed or unsigned envelopes both work.

    ### Required attributes

    <Properties>
      <Property name="network" type="string">
        `testnet` or `pubnet`. Must match the server's network, otherwise `400 WRONG_NETWORK` (the error tells you which network the server runs).
      </Property>
      <Property name="transactionXdr" type="string">
        Base64 `TransactionEnvelope` XDR. A fee-bump envelope is analysed through its inner transaction.
      </Property>
    </Properties>

    ### Optional attributes

    <Properties>
      <Property name="policy" type="object">
        Your rules. Every option is optional, and the default is `{}`. See [Policy](/policies).
      </Property>
      <Property name="userWallet" type="string">
        A Stellar `G…` address: the account whose balances to evaluate. Required for `maxLossPercent` and `minPostUsdcBalance`; without it those rules block (fail-closed) and the response is marked low confidence.
      </Property>
      <Property name="integratorRequestId" type="string">
        Your own correlation id, up to 256 characters. Echoed in `meta`.
      </Property>
      <Property name="paymentRequirements" type="object">
        For x402 payments: the merchant's published requirements (`scheme`, `network`, `asset`, `amount`, `payTo`, `maxTimeoutSeconds`, `extra`). Baret checks that the payee and asset appear in the transaction.
      </Property>
    </Properties>

    Errors: `400 BAD_REQUEST` (invalid body or XDR), `400 WRONG_NETWORK`, `401`, `429`, `502 RPC_ERROR` and `504 RPC_ERROR` when Horizon or Soroban RPC fails or times out. See [Errors](/errors).

  </Col>

    <CodeGroup tag="POST" label="/v1/analyze">

    ```bash {{ title: 'cURL' }}
    curl -X POST https://baret-stellar.onrender.com/v1/analyze \
      -H "Authorization: Bearer $BARET_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "network": "testnet",
        "transactionXdr": "AAAAAgAAAACd…",
        "userWallet": "GAT3XUNP…",
        "policy": {
          "maxLossPercent": 50,
          "blockAccountMerge": true,
          "blockSignerChanges": true,
          "blockMasterKeyRemoval": true
        }
      }'
    ```

    ```js {{ title: 'JavaScript' }}
    const verdict = await fetch('https://baret-stellar.onrender.com/v1/analyze', {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${process.env.BARET_KEY}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        network: 'testnet',
        transactionXdr,
        userWallet,
        policy: { blockAccountMerge: true, maxLossPercent: 50 },
      }),
    }).then((r) => r.json())

    if (!verdict.safe) {
      throw new Error(verdict.reasons.join('; '))
    }
    ```

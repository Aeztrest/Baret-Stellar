# Errors

Every error comes in the same envelope, with a stable machine-readable `code` and a human `message`. Switch on `code`; the message may change. {{ className: 'lead' }}

<Row>
  <Col>

    <Properties>
      <Property name="error.code" type="string">
        One of the codes below.
      </Property>
      <Property name="error.message" type="string">
        A description for humans. Written so it does not expose upstream URLs or server internals.
      </Property>
      <Property name="error.details" type="object">
        Optional context: validation `issues`, the server's and requested network, `retryAfterSeconds`, and so on.
      </Property>
    </Properties>

    Every response, success or error, carries an `X-Request-Id` header. Include it when you report a problem.

  </Col>
  <Col>

    <CodeGroup>

    ```json {{ title: 'Error response' }}
    {
      "error": {
        "code": "WRONG_NETWORK",
        "message": "Server is configured for testnet, request asked for pubnet",
        "details": {
          "serverNetwork": "testnet",
          "requestedNetwork": "pubnet"
        }
      }
    }
    ```

    </CodeGroup>

  </Col>
</Row>

## Error codes

<Properties>
  <Property name="BAD_REQUEST" type="400">
    The body is malformed, a field is missing or invalid, or the transaction XDR cannot be decoded. `details.issues` lists the failing fields for validation errors. Also used for other client errors, such as invalid JSON.
  </Property>
  <Property name="UNAUTHORIZED" type="401">
    No API key, or an invalid or revoked one. Create a key with `POST /v1/keys`. The response includes `WWW-Authenticate: Bearer realm="baret"`.
  </Property>
  <Property name="FORBIDDEN" type="403">
    Not allowed here. Today: `POST /v1/keys` when the operator turned self-service keys off.
  </Property>
  <Property name="NOT_FOUND" type="404">
    No route for that method and path.
  </Property>
  <Property name="PAYLOAD_TOO_LARGE" type="413">
    The body exceeds the server's limit (1 MiB by default; `details.maxBodyBytes`).
  </Property>
  <Property name="RATE_LIMITED" type="429">
    You exceeded your key's per-minute budget, the per-IP limit, or the per-IP key-creation throttle. Wait `Retry-After` seconds (also `details.retryAfterSeconds`).
  </Property>
  <Property name="WRONG_NETWORK" type="400">
    The request's `network` is not the network this server runs. `details` holds `serverNetwork` and `requestedNetwork`.
  </Property>
  <Property name="RPC_ERROR" type="502 / 504">
    Horizon or Soroban RPC failed or did not answer in time (`504` for a timeout, `502` otherwise; `details.rpcCode` says which). Not retried by the server; retry it yourself.
  </Property>
  <Property name="FACILITATOR_ERROR" type="502">
    The x402 facilitator failed while verifying or settling a paid `POST /v1/analyze`. Distinct from a policy verdict.
  </Property>
  <Property name="UNAVAILABLE" type="503">
    The server cannot do this right now. Today: the key store is full and no new keys are being issued.
  </Property>
  <Property name="INTERNAL_ERROR" type="500">
    Something unexpected went wrong on the server. Report it with the `X-Request-Id`.
  </Property>
</Properties>

## Other statuses

<Properties>
  <Property name="200" type="OK">
    The API worked. `safe: false` in the body is still a `200`: the verdict is data, not an error.
  </Property>
  <Property name="402" type="Payment Required">
    Only on `POST /v1/analyze` of a server with x402 enabled, when you sent neither a valid key nor a payment. The `PAYMENT-REQUIRED` header describes what to pay.
  </Property>
  <Property name="422" type="Unprocessable">
    `POST /mcp/call` when the tool call itself failed (the body has `isError: true`).
  </Property>
</Properties>

<Note>
  Inside a **batch** or a **stream**, a failing item does not fail the request.
  It appears as a result with `status: "error"` and an `error` object holding a
  `code` and `message` from the list above.
</Note>

<Note>
  The `/demo/scrybe` and `/demo/cortex` routes (the x402 demo merchants) predate
  this envelope and reply with a plain `{ "error": "…" }` object.
</Note>

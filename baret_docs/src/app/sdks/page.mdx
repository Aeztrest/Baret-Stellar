# SDKs & Integrations

Baret is an HTTP API first. On top of it there are two TypeScript packages, a command-line tool and MCP tools for LLM agents. {{ className: 'lead' }}

<Note>
  The TypeScript packages live in the Baret repository as workspace packages
  (`@stellar-thorn/agent-guard`, `@stellar-thorn/swig-guard`) and are marked
  private: they are **not published to npm**. Use them from a checkout of the
  monorepo, or call the REST API directly from any language.
</Note>

---

## Agent SDK and CLI {{ id: 'agent-sdk' }}

`@stellar-thorn/agent-guard` puts Baret in front of an autonomous agent's signing key. The agent builds a transaction; `AgentWallet` sends it to `/v1/analyze`, applies your policy, and signs and submits **only if the policy allows**. If the server cannot be reached it does **not** sign (fail-closed).

<CodeGroup>

```ts {{ title: 'AgentWallet' }}
import { AgentWallet } from '@stellar-thorn/agent-guard'

const agent = AgentWallet.fromSecret(process.env.BARET_AGENT_SECRET!, {
  serverUrl: 'https://baret-stellar.onrender.com',
  apiKey: process.env.BARET_API_KEY,
  network: 'testnet',
  policy: 'balanced', // 'strict' | 'balanced' | 'permissive' | a policy object
})

try {
  const { hash, explorerUrl } = await agent.guardedSubmit(transactionXdr)
} catch (err) {
  // GuardBlockedError: the policy refused it and the key never signed
  // AnalyzeError: the server was unreachable (nothing was signed)
}
```

</CodeGroup>

<Properties>
  <Property name="evaluate(xdr)" type="advisory">
    Returns the verdict. Never touches the key. Use it when you sign yourself.
  </Property>
  <Property name="guardedSign(xdr)" type="sign">
    Evaluates, then signs locally only if allowed. Throws `GuardBlockedError` otherwise.
  </Property>
  <Property name="guardedSubmit(xdr)" type="sign + send">
    `guardedSign`, then broadcasts through Horizon and returns the hash and an explorer link.
  </Property>
</Properties>

To detect a compromised server or proxy, pin the server's signing key (`pinnedServerPublicKey`, or `BARET_PINNED_SERVER_PUBLIC_KEY`). Every verdict's Ed25519 attestation is then verified against your own recomputation of the transaction hash, and a missing or invalid one throws `AttestationError` (fail-closed). See [Analyze](/analyze) for how attestations work.

The same thing is available as a command, usable from any language through its exit code:

<CodeGroup>

```bash {{ title: 'baret CLI' }}
export BARET_API_URL=https://baret-stellar.onrender.com
export BARET_API_KEY=baret_…
export BARET_AGENT_SECRET=S…        # only for sign / submit; never written to disk

echo "$XDR" | baret submit -
# exit 0: allowed and sent   1: blocked by policy   2: error (bad input, server unreachable)
```

</CodeGroup>

Commands: `baret analyze`, `sign`, `submit`, `address`, `init`, `policy list`. Configuration order: flags, then `BARET_*` environment variables, then `~/.baret/config.json`, then defaults. The API key can only be given through `BARET_API_KEY`.

## Guard SDK for wallets {{ id: 'guard-sdk' }}

`@stellar-thorn/swig-guard` is the SDK the Baret extension itself is built on. It has **no dependency on the Stellar SDK** so it is safe to bundle in a browser. It holds the wallet policy type and the Strict, Balanced and Permissive templates, and a client for `/v1/analyze`. It never signs or submits.

<CodeGroup>

```ts {{ title: 'TransactionGuard' }}
import { TransactionGuard, BALANCED_POLICY } from '@stellar-thorn/swig-guard'

const guard = new TransactionGuard({
  analyze: { baseUrl: 'https://baret-stellar.onrender.com', apiKey: BARET_KEY },
  network: 'testnet',
})

const result = await guard.evaluate({
  transactionXdr,
  userWallet: 'GAT3XUNP…',
  policy: BALANCED_POLICY,
})

if (result.decision === 'block') {
  showWarning(result.blockingReasons) // result.analysis has the whole verdict
}
```

</CodeGroup>

If the server cannot be reached, `evaluate` throws `AnalyzeError`: treat that as "unsafe to sign" unless you deliberately choose otherwise. A plain `http://` server URL is refused unless it is a loopback address (or you set `allowInsecureHttp`), because without TLS a network attacker could forge a `safe: true` answer. Pass `paymentRequirements` when the transaction is an x402 payment.

## MCP tools {{ id: 'mcp-server' }}

Baret exposes [Model Context Protocol](https://modelcontextprotocol.io/)-style tools over HTTP so an LLM agent can ask "is this safe to sign?". Both routes need an API key.

<Properties>
  <Property name="GET /mcp/tools" type="list">
    The tool descriptors with JSON Schema inputs.
  </Property>
  <Property name="POST /mcp/call" type="call">
    Body `{ "tool": "…", "arguments": { … } }`. A failing tool returns `422` with `isError: true`.
  </Property>
</Properties>

<Properties>
  <Property name="baret_analyze" type="tool">
    Input: `transactionXdr` (required), `network` (defaults to the server's network), `userWallet`. Returns a Markdown summary of the verdict, findings, balance changes and the authorization trace, written for a model to read. It runs with an **empty policy**; the `policyProfile` argument the descriptor lists is not applied.
  </Property>
  <Property name="baret_health" type="tool">
    Reports the server's network and endpoints.
  </Property>
  <Property name="baret_list_profiles" type="tool">
    Lists policy profile names. Profiles are informational; use the `policy` object with the REST API for real control.
  </Property>
</Properties>

<CodeGroup>

```bash {{ title: 'Call a tool' }}
curl -X POST https://baret-stellar.onrender.com/mcp/call \
  -H "Authorization: Bearer $BARET_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "tool": "baret_analyze", "arguments": { "transactionXdr": "AAAAAgAAAACd…", "network": "testnet" } }'
# { "content": [ { "type": "text", "text": "## Transaction Analysis Result\n**Verdict**: SAFE\n…" } ] }
```

</CodeGroup>

## REST API {{ id: 'rest-api' }}

Any language that can make an HTTPS request can integrate. The machine-readable spec is `GET /openapi.json` (OpenAPI 3.0, served live by every server); generate a client from it if you like.

<CodeGroup>

```bash {{ title: 'cURL' }}
curl -X POST https://baret-stellar.onrender.com/v1/analyze \
  -H "Authorization: Bearer $BARET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"network":"testnet","transactionXdr":"…"}'
```

```js {{ title: 'JavaScript' }}
const res = await fetch('https://baret-stellar.onrender.com/v1/analyze', {
  method: 'POST',
  headers: { Authorization: `Bearer ${BARET_KEY}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ network: 'testnet', transactionXdr }),
})
const { safe, reasons, riskFindings } = await res.json()
```

```python {{ title: 'Python' }}
import requests

verdict = requests.post(
    'https://baret-stellar.onrender.com/v1/analyze',
    headers={'Authorization': f'Bearer {BARET_KEY}'},
    json={'network': 'testnet', 'transactionXdr': transaction_xdr},
    timeout=30,
).json()
```

```go {{ title: 'Go' }}
body, _ := json.Marshal(map[string]any{
    "network":        "testnet",
    "transactionXdr": txXDR,
})
req, _ := http.NewRequest("POST", "https://baret-stellar.onrender.com/v1/analyze", bytes.NewReader(body))
req.Header.Set("Authorization", "Bearer "+key)
req.Header.Set("Content-Type", "application/json")
resp, _ := http.DefaultClient.Do(req)
```

</CodeGroup>

<Note>
  Unlike the SDKs, plain REST has no built-in fail-closed behaviour. If the call
  fails or times out, decide deliberately what your application does: for a
  signing flow the safe default is to **not sign**.
</Note>
